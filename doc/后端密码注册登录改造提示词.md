# 后端改造提示词：C 端密码注册 / 密码登录

> 将本提示词交给后端 Agent / 开发者，在 `uniqmag-admin/backend` 中实现。  
> 对齐现有文档：`backend/docs/app-api.md`、实现：`internal/handler/app_auth.go`。  
> **目标**：在保留短信验证码登录的前提下，新增密码注册与密码登录，供官网前端联调。

---

## 背景

官网前端（`webiste-future`）已同时支持：

1. **短信验证码登录**（已对接）：`POST /app/v1/auth/sms/send`、`POST /app/v1/auth/sms/login`
2. **密码登录**：`POST /app/v1/auth/login`（待实现）
3. **密码注册**：`POST /app/v1/auth/register`（待实现）

前端调用约定与现有 C 端 API 一致：

- Base：`/app/v1`
- 响应信封：`{ success, data }` / `{ success: false, errorMessage }`
- 成功登录后签发 **App JWT**（`typ=app`），与短信登录相同
- 手机号：`^1[3-9]\d{9}$`

前端已写死的路径与字段名请勿改名，否则会破坏联调。

## 1. 数据库变更

当前 `app_user` 大致为：

```sql
CREATE TABLE IF NOT EXISTS app_user (
    id                BIGSERIAL PRIMARY KEY,
    mobile            TEXT NOT NULL UNIQUE,
    nickname          TEXT,
    profile_completed BOOLEAN NOT NULL DEFAULT FALSE,
    status            TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'disabled')),
    created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_login_at     TIMESTAMPTZ
);
```

请增量迁移（兼容已有短信用户）：

```sql
ALTER TABLE app_user
  ADD COLUMN IF NOT EXISTS password_hash TEXT,
  ADD COLUMN IF NOT EXISTS email TEXT;

-- 可选：邮箱唯一（允许 NULL；非空时唯一）
CREATE UNIQUE INDEX IF NOT EXISTS idx_app_user_email_unique
  ON app_user (email)
  WHERE email IS NOT NULL AND email <> '';
```

约束说明：

| 字段 | 说明 |
|------|------|
| `password_hash` | bcrypt；短信自动建号用户可为 `NULL`（无密码，仅能验证码登录） |
| `email` | 可选；注册时可传 |

密码哈希请复用项目已有 bcrypt 写法（参考 `AdminStore` / `UserStore`）。

## 2. 密码注册

`POST /app/v1/auth/register`（公开，无需 Bearer）

### 请求

```json
{
  "mobile": "13800138000",
  "password": "secret12",
  "nickname": "小明",
  "email": "ming@example.com"
}
```

| 字段 | 类型 | 必填 | 规则 |
|------|------|:----:|------|
| mobile | string | ✓ | `^1[3-9]\d{9}$` |
| password | string | ✓ | 长度 ≥ 6 |
| nickname | string | ✓ | trim 后非空；Unicode 长度 1–32 |
| email | string | | 可选；若传须为合法邮箱格式 |

### 成功行为

1. 若 `mobile` 已存在 → 失败：`该手机号已注册`
2. 创建 `app_user`：
   - `password_hash` = bcrypt(password)
   - `nickname` = trim(nickname)
   - `email` = trim(email) 或 NULL
   - `profile_completed` = **true**（注册时已带昵称）
   - `status` = `active`
3. 签发 App JWT，更新 `last_login_at`
4. 返回结构与短信登录成功一致：

```json
{
  "success": true,
  "data": {
    "token": "<jwt>",
    "is_new_user": true,
    "profile_completed": true,
    "user": {
      "id": 1,
      "mobile": "138****8000",
      "nickname": "小明",
      "profile_completed": true,
      "status": "active"
    }
  }
}
```

### 失败 `errorMessage`（建议文案，前端会原样展示）

| 文案 | 场景 |
|------|------|
| 参数错误 | 缺字段 / 手机号非法 / 昵称非法 / 密码过短 / 邮箱格式错误 |
| 该手机号已注册 | mobile 冲突 |
| 注册失败 | 写库失败 |
| 签发 token 失败 | JWT 失败 |

## 3. 密码登录

`POST /app/v1/auth/login`（公开）

### 请求

```json
{
  "mobile": "13800138000",
  "password": "secret12"
}
```

| 字段 | 类型 | 必填 | 规则 |
|------|------|:----:|------|
| mobile | string | ✓ | 大陆手机号 |
| password | string | ✓ | 非空（建议仍校验 ≥ 6，或与注册一致） |

### 成功行为

1. 按 mobile 查用户；不存在 → `手机号或密码错误`（勿泄露是否注册）
2. `status=disabled` → `账号已禁用`
3. `password_hash` 为空 → `请使用验证码登录或先设置密码`（该账号仅短信注册）
4. bcrypt 校验失败 → `手机号或密码错误`
5. 签发 App JWT，更新 `last_login_at`
6. 返回：

```json
{
  "success": true,
  "data": {
    "token": "<jwt>",
    "is_new_user": false,
    "profile_completed": true,
    "user": { "...AppUserPublic..." }
  }
}
```

`profile_completed` / `user` 以库中实际值为准（若历史数据未完善昵称，可为 false，前端会跳转完善昵称页）。

### 失败文案

| 文案 | 场景 |
|------|------|
| 参数错误 | 缺字段 / 手机号非法 |
| 手机号或密码错误 | 用户不存在或密码不对 |
| 账号已禁用 | disabled |
| 请使用验证码登录或先设置密码 | 无 `password_hash` |
| 登录失败 / 签发 token 失败 | 内部错误 |

## 4. 与短信登录的关系（重要）

| 场景 | 期望 |
|------|------|
| 仅短信登录建号 | `password_hash=NULL`，仍可短信登录；密码登录提示「请使用验证码登录…」 |
| 密码注册 | 有密码 + 昵称已完成，可密码登录，也可后续用同一手机号短信登录 |
| 短信用户再密码注册 | 应失败「该手机号已注册」（同一 `mobile` UNIQUE） |
| 同一 JWT | 密码登录与短信登录签发同一套 App token |

可选后续（本次可不做，但可在文档标注）：

- `PUT /app/v1/me/password`：已登录用户为账号设置/修改密码（方便短信用户补设密码）

## 6. 联调 curl（实现后自测）

```bash
BASE=http://127.0.0.1:8080

# 注册
curl -s -X POST "$BASE/app/v1/auth/register" \
  -H 'Content-Type: application/json' \
  -d '{"mobile":"13900139000","password":"secret12","nickname":"测试用户","email":"t@example.com"}'

# 密码登录
curl -s -X POST "$BASE/app/v1/auth/login" \
  -H 'Content-Type: application/json' \
  -d '{"mobile":"13900139000","password":"secret12"}'

# 读资料
curl -s "$BASE/app/v1/me" -H "Authorization: Bearer TOKEN"
```
